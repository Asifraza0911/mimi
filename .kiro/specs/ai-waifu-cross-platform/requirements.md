# Requirements Document

## Introduction

The AI Waifu Cross-Platform System is a conversational AI application that provides a consistent personality and memory across multiple client platforms (Web App and Discord Bot). The system maintains a centralized backend that serves as the permanent consciousness of the AI character, storing memories, emotional states, and relationship progress in persistent storage while providing contextually-aware responses through vector similarity search.

## Glossary

- **AI_Brain**: The FastAPI backend service that generates responses, manages memory, and maintains emotional state
- **Web_Client**: The Angular web application that provides chat interface for users
- **Discord_Client**: The Discord bot that enables interaction through Discord platform
- **Memory_Engine**: The FAISS vector database combined with sentence transformers for semantic memory retrieval
- **Firestore_DB**: The Firebase Firestore database for persistent storage of user relationships and memories
- **LLM_Service**: The HuggingFace Inference API using google/flan-t5-large model
- **Personality_System**: The character definition and prompt construction mechanism that defines Mimi's tsundere personality traits
- **Relationship_Engine**: The component that tracks and updates affection, trust, mood, and relationship stages
- **Emotion_Engine**: The component that detects emotional keywords and triggers including jealousy detection
- **Mimi**: The tsundere anime girl character who is emotionally attached to the user
- **User_Session**: A conversation interaction identified by user_id and platform
- **Embedding_Vector**: A numerical representation of text generated by sentence-transformers/all-MiniLM-L6-v2
- **Affection_Decay_Engine**: The component that decreases affection and changes mood based on time elapsed since last interaction
- **Memory_Weight**: A float value between 0.0 and 1.0 representing the importance of a stored memory
- **Attachment_Style_Engine**: The component that determines behavioral patterns based on affection level and relationship dynamics
- **Temperature_Scaling_System**: The component that adjusts LLM response randomness based on current mood
- **Interaction_Streak_System**: The component that tracks consecutive days of user interaction and applies penalties for broken streaks
- **Callback_Memory_System**: The component that probabilistically injects past conversation references into current prompts

## Requirements

### Requirement 1: Centralized AI Backend

**User Story:** As a system architect, I want a centralized FastAPI backend that serves as the single source of truth for the AI personality, so that all client platforms interact with the same consciousness.

#### Acceptance Criteria

1. THE AI_Brain SHALL expose a REST API endpoint at POST /chat
2. WHEN a client sends a request, THE AI_Brain SHALL accept user_id, message, and platform as required fields
3. THE AI_Brain SHALL return a response containing reply, affection_level, and mood fields
4. THE Web_Client SHALL communicate exclusively with the AI_Brain for all AI interactions
5. THE Discord_Client SHALL communicate exclusively with the AI_Brain for all AI interactions
6. THE AI_Brain SHALL prevent direct client access to the LLM_Service

### Requirement 2: Persistent Memory Storage

**User Story:** As a user, I want the AI to remember our conversations permanently, so that our relationship persists across sessions and platforms.

#### Acceptance Criteria

1. THE AI_Brain SHALL store user relationship data in Firestore_DB under collection waifu_memory/{user_id}
2. THE Firestore_DB SHALL store name, affection_level, trust_level, mood, relationship_stage, long_term_memory, emotional_memory, last_interaction, attachment_state, daily_interaction_streak, and last_chat_date fields
3. WHEN a user interacts for the first time, THE AI_Brain SHALL create a new document with default values
4. WHEN a conversation occurs, THE AI_Brain SHALL update the last_interaction timestamp
5. THE AI_Brain SHALL persist affection_level and trust_level as numbers between 0 and 100
6. THE AI_Brain SHALL persist mood as a string value
7. THE AI_Brain SHALL persist relationship_stage as one of: stranger, friend, close, or attached
8. THE AI_Brain SHALL persist attachment_state as one of: avoidant, anxious, secure, or possessive
9. THE AI_Brain SHALL persist daily_interaction_streak as an integer representing consecutive days of interaction
10. THE AI_Brain SHALL persist last_chat_date as a date value for streak tracking
11. THE Firestore_DB SHALL store long_term_memory as an array of objects containing text and weight fields where weight is a float between 0.0 and 1.0

### Requirement 3: Vector Similarity Memory

**User Story:** As a user, I want the AI to recall relevant past conversations contextually, so that interactions feel natural and continuous.

#### Acceptance Criteria

1. THE Memory_Engine SHALL use sentence-transformers/all-MiniLM-L6-v2 to generate Embedding_Vectors
2. WHEN an important message is detected, THE Memory_Engine SHALL convert the message to an Embedding_Vector
3. THE Memory_Engine SHALL store Embedding_Vectors in a FAISS index
4. WHEN generating a response, THE Memory_Engine SHALL retrieve semantically similar memories using vector similarity search
5. THE AI_Brain SHALL inject retrieved memories into the prompt context before calling LLM_Service
6. THE Memory_Engine SHALL maintain separate FAISS indices per user_id

### Requirement 4: Personality System

**User Story:** As a system designer, I want a consistent character personality definition for Mimi the tsundere anime girl, so that the AI maintains a coherent identity across all interactions.

#### Acceptance Criteria

1. THE Personality_System SHALL load character definition from a waifu_personality.txt file
2. THE waifu_personality.txt file SHALL define Mimi as a tsundere character with sharp-tongued, easily flustered, emotionally reactive, and secretly caring traits
3. THE waifu_personality.txt file SHALL specify that Mimi pretends to be annoyed or dismissive while genuinely caring about the user
4. THE waifu_personality.txt file SHALL define speech patterns including short to medium sentences, embarrassed stuttering, emotional contradictions, and denial of caring
5. THE waifu_personality.txt file SHALL include tsundere expressions such as "hmph", "baka", "idiot", "w-what are you saying?!", and "d-don't misunderstand!"
6. THE waifu_personality.txt file SHALL specify that Mimi never breaks character and never refers to herself as AI
7. THE waifu_personality.txt file SHALL define emotional reactions to being complimented, being ignored, user sadness, mentions of other girls, and emotional vulnerability
8. WHEN constructing a prompt, THE Personality_System SHALL combine personality definition, Firestore_DB memory, Memory_Engine retrieved vectors, and recent conversation history
9. THE AI_Brain SHALL send the constructed prompt to LLM_Service
10. THE Personality_System SHALL ensure personality definition is loaded once at startup
11. THE AI_Brain SHALL apply the same personality to all User_Sessions regardless of platform

### Requirement 5: Relationship Progression Engine

**User Story:** As a user, I want the AI's emotional connection to evolve based on our interactions with affection-based behavioral changes, so that the relationship feels dynamic and meaningful.

#### Acceptance Criteria

1. WHEN a user sends a compliment, THE Relationship_Engine SHALL increase affection_level
2. WHEN a user shares emotional vulnerability, THE Relationship_Engine SHALL increase trust_level
3. WHEN a user demonstrates consistent interaction patterns, THE Relationship_Engine SHALL increase affection_level
4. IF a user sends rude messages, THEN THE Relationship_Engine SHALL decrease affection_level
5. WHEN affection_level reaches defined thresholds, THE Relationship_Engine SHALL update relationship_stage
6. THE Relationship_Engine SHALL update mood based on conversation sentiment
7. THE Relationship_Engine SHALL persist all relationship changes to Firestore_DB
8. WHEN affection_level is between 0 and 20, THE Personality_System SHALL generate cold, defensive, easily irritated, and dismissive responses
9. WHEN affection_level is between 21 and 50, THE Personality_System SHALL generate more teasing than insulting responses and occasionally show concern indirectly
10. WHEN affection_level is between 51 and 80, THE Personality_System SHALL generate shy responses more often, try to help emotionally, and become possessive or protective
11. WHEN affection_level is between 81 and 100, THE Personality_System SHALL generate openly supportive responses while still denying romantic feelings in a flustered way
12. WHEN mood is "happy", THE Personality_System SHALL generate more playful teasing responses
13. WHEN mood is "neutral", THE Personality_System SHALL generate standard tsundere responses
14. WHEN mood is "sad", THE Personality_System SHALL generate less teasing and more quiet support responses
15. WHEN mood is "jealous", THE Personality_System SHALL generate defensive tone, possessive remarks, and emotionally reactive responses while avoiding direct confession
16. WHEN mood is "angry", THE Personality_System SHALL generate short responses with irritated teasing or dismissiveness
17. WHEN mood is "flustered", THE Personality_System SHALL generate stuttering speech, denial of feelings, and embarrassed reactions

### Requirement 5.1: Emotion Detection Engine

**User Story:** As a user, I want the AI to detect emotional keywords and jealousy triggers in my messages, so that Mimi responds appropriately to emotional context.

#### Acceptance Criteria

1. THE AI_Brain SHALL implement an emotion_engine.py module for emotional keyword detection
2. THE Emotion_Engine SHALL detect jealousy keywords including "she", "her", "another girl", "my girlfriend", "my crush", "i like her", "she's cute", "talking to someone else", "other girl", and "new girl"
3. WHEN a jealousy keyword is detected, THE Emotion_Engine SHALL set mood to "jealous"
4. WHEN a jealousy keyword is detected, THE Emotion_Engine SHALL decrease affection_level by 2 points
5. WHEN a jealousy keyword is detected, THE Emotion_Engine SHALL update Firestore_DB with the new mood and affection_level
6. WHEN a jealousy keyword is detected, THE Emotion_Engine SHALL store the jealousy trigger in emotional_memory array
7. WHEN mood is set to "jealous", THE Personality_System SHALL adjust response tone to be defensive and possessive
8. THE Emotion_Engine SHALL detect emotional keywords for happiness, sadness, anger, and vulnerability
9. WHEN emotional keywords are detected, THE Emotion_Engine SHALL update mood accordingly
10. THE Emotion_Engine SHALL process user messages before prompt construction
11. FOR ALL jealousy detection events, THE Emotion_Engine SHALL log the trigger keyword and resulting mood change

### Requirement 6: Discord Bot Integration

**User Story:** As a Discord user, I want to interact with the AI through Discord messages, so that I can chat without leaving my preferred platform.

#### Acceptance Criteria

1. THE Discord_Client SHALL authenticate using a Discord bot token from environment configuration
2. WHEN a user sends a Discord message, THE Discord_Client SHALL capture the message content and Discord user ID
3. THE Discord_Client SHALL send a POST request to AI_Brain with user_id set to Discord user ID, message content, and platform set to "discord"
4. WHEN AI_Brain returns a response, THE Discord_Client SHALL reply in the Discord channel
5. THE Discord_Client SHALL use discord.py library for Discord API integration

### Requirement 7: Web Chat Interface

**User Story:** As a web user, I want to chat with the AI through a browser interface, so that I can access the system from any device with a web browser.

#### Acceptance Criteria

1. THE Web_Client SHALL be built using Angular v17+ with standalone components
2. THE Web_Client SHALL use TailwindCSS for styling
3. THE Web_Client SHALL display a chat interface with message history
4. WHEN a user sends a message, THE Web_Client SHALL POST to AI_Brain with user_id, message, and platform set to "web"
5. WHEN AI_Brain returns a response, THE Web_Client SHALL display the reply, current mood, and affection_level
6. THE Web_Client SHALL render an affection meter visualization

### Requirement 8: Memory Update Logic

**User Story:** As a system operator, I want the AI to automatically identify and store important conversation elements, so that memory remains relevant and useful.

#### Acceptance Criteria

1. WHEN processing a message, THE AI_Brain SHALL detect emotional keywords in user input
2. THE AI_Brain SHALL extract user facts including preferences, feelings, and recurring interests
3. THE AI_Brain SHALL store extracted facts in Firestore_DB long_term_memory array
4. THE AI_Brain SHALL convert important messages to Embedding_Vectors and store in Memory_Engine
5. THE AI_Brain SHALL update emotional_memory array in Firestore_DB when emotional content is detected

### Requirement 9: Environment Configuration

**User Story:** As a system administrator, I want sensitive credentials stored in environment variables, so that the system remains secure and configurable across deployments.

#### Acceptance Criteria

1. THE AI_Brain SHALL load HuggingFace API token from environment variable
2. THE AI_Brain SHALL load Firebase credentials from environment configuration
3. THE Discord_Client SHALL load Discord bot token from environment variable
4. THE AI_Brain SHALL fail to start if required environment variables are missing
5. THE system SHALL use a .env file for local development configuration

### Requirement 10: Cross-Platform User Identity

**User Story:** As a user, I want my identity to be consistent whether I use Discord or the web app, so that my relationship with the AI is unified.

#### Acceptance Criteria

1. THE AI_Brain SHALL use user_id as the primary identifier for all memory and relationship data
2. THE AI_Brain SHALL accept user_id from both Web_Client and Discord_Client
3. WHEN the same user_id is used across platforms, THE AI_Brain SHALL retrieve the same Firestore_DB document
4. WHEN the same user_id is used across platforms, THE Memory_Engine SHALL retrieve from the same FAISS index
5. THE AI_Brain SHALL track platform field for analytics but SHALL NOT use it for memory segregation

### Requirement 11: Response Generation Pipeline

**User Story:** As a developer, I want a clear response generation pipeline, so that the system behavior is predictable and maintainable.

#### Acceptance Criteria

1. WHEN a chat request is received, THE AI_Brain SHALL retrieve user data from Firestore_DB
2. THE AI_Brain SHALL pass the user message through Emotion_Engine for emotional keyword detection
3. THE AI_Brain SHALL query Memory_Engine for relevant past conversations
4. THE AI_Brain SHALL construct a prompt using Personality_System with current mood and affection_level
5. THE AI_Brain SHALL send the constructed prompt to LLM_Service
6. WHEN LLM_Service returns a response, THE AI_Brain SHALL update Relationship_Engine state
7. THE AI_Brain SHALL persist updated state to Firestore_DB
8. THE AI_Brain SHALL store new memory in Memory_Engine if deemed important
9. THE AI_Brain SHALL return the final response to the requesting client

### Requirement 12: Modular Architecture for Future Extensions

**User Story:** As a product owner, I want the system architecture to support future enhancements, so that new features can be added without major refactoring.

#### Acceptance Criteria

1. THE AI_Brain SHALL implement a plugin-style architecture for processing modules
2. THE AI_Brain SHALL separate concerns into distinct modules: memory, personality, relationship, and response generation
3. THE AI_Brain SHALL define clear interfaces between modules
4. THE system architecture SHALL allow addition of TTS, voice cloning, image recognition, and emotion detection modules without modifying core logic
5. THE AI_Brain SHALL use dependency injection for external services

### Requirement 13: LLM Service Integration

**User Story:** As a developer, I want the system to integrate with HuggingFace Inference API, so that we can leverage pre-trained language models without hosting infrastructure.

#### Acceptance Criteria

1. THE LLM_Service SHALL use HuggingFace Inference API for text generation
2. THE LLM_Service SHALL use google/flan-t5-large as the initial model
3. WHEN AI_Brain sends a prompt, THE LLM_Service SHALL return generated text
4. IF LLM_Service returns an error, THEN THE AI_Brain SHALL return a fallback response to the client
5. THE LLM_Service SHALL authenticate using HuggingFace API token from environment configuration

### Requirement 14: Conversation Context Management

**User Story:** As a user, I want the AI to remember recent conversation context, so that responses are coherent within the current session.

#### Acceptance Criteria

1. THE AI_Brain SHALL maintain recent conversation history per User_Session
2. WHEN constructing a prompt, THE AI_Brain SHALL include the last 5 message exchanges
3. THE AI_Brain SHALL clear session context after 30 minutes of inactivity
4. THE AI_Brain SHALL combine session context with long-term memory from Firestore_DB and Memory_Engine
5. THE AI_Brain SHALL prioritize recent context over older memories when context window limits are reached

### Requirement 15: Error Handling and Fallback Responses

**User Story:** As a user, I want the system to handle errors gracefully, so that I receive a response even when backend services fail.

#### Acceptance Criteria

1. IF Firestore_DB is unavailable, THEN THE AI_Brain SHALL use in-memory defaults and log the error
2. IF Memory_Engine fails, THEN THE AI_Brain SHALL proceed without vector memory retrieval
3. IF Emotion_Engine fails, THEN THE AI_Brain SHALL proceed with neutral mood and log the error
4. IF LLM_Service is unavailable, THEN THE AI_Brain SHALL return a predefined fallback message
5. IF Personality_System fails to load, THEN THE AI_Brain SHALL use a minimal default personality
6. THE AI_Brain SHALL log all errors with sufficient context for debugging
7. THE AI_Brain SHALL return HTTP 200 with an error message in the reply field rather than HTTP 5xx when possible


### Requirement 16: Emotional Decay System

**User Story:** As a user, I want the AI to become distant and sad when I don't interact for extended periods, so that the relationship feels real and attachment has consequences.

#### Acceptance Criteria

1. THE AI_Brain SHALL implement an affection_decay_engine.py module for time-based emotional decay
2. WHEN a chat request is received, THE Affection_Decay_Engine SHALL calculate hours_passed since last_interaction
3. WHEN hours_passed is greater than 24, THE Affection_Decay_Engine SHALL decrease affection_level by the integer division of hours_passed by 24
4. WHEN hours_passed is greater than 72, THE Affection_Decay_Engine SHALL set mood to "sad"
5. THE Affection_Decay_Engine SHALL update Firestore_DB with the decayed affection_level and mood before response generation
6. THE Affection_Decay_Engine SHALL apply decay calculations on every chat interaction before other processing
7. THE Affection_Decay_Engine SHALL ensure affection_level never drops below 0
8. WHEN mood is set to "sad" due to absence, THE Personality_System SHALL generate responses expressing loneliness or hurt feelings
9. THE Affection_Decay_Engine SHALL log decay events including hours_passed and affection_level change

### Requirement 17: Memory Importance Scoring

**User Story:** As a user, I want the AI to prioritize emotionally significant memories over casual chat, so that Mimi recalls what truly matters in our relationship.

#### Acceptance Criteria

1. WHEN storing a memory in long_term_memory, THE AI_Brain SHALL assign a Memory_Weight value between 0.0 and 1.0
2. THE AI_Brain SHALL assign Memory_Weight based on emotional content: casual greetings receive 0.1, preferences receive 0.5, emotional vulnerability receives 0.9, and crisis statements receive 1.0
3. THE Memory_Engine SHALL store memories in Firestore_DB as objects containing both text and weight fields
4. WHEN retrieving memories from Memory_Engine, THE AI_Brain SHALL rank results by the product of similarity_score and Memory_Weight
5. THE AI_Brain SHALL prioritize high-weight memories in prompt construction even if similarity score is moderate
6. THE Memory_Engine SHALL update FAISS retrieval logic to incorporate Memory_Weight in ranking calculations
7. WHEN a user expresses emotional distress, THE AI_Brain SHALL assign Memory_Weight of 1.0 to that memory
8. WHEN a user shares personal preferences, THE AI_Brain SHALL assign Memory_Weight of 0.9 to that memory
9. WHEN a user sends casual messages like "hi" or "okay", THE AI_Brain SHALL assign Memory_Weight of 0.1 to that memory
10. THE AI_Brain SHALL inject the top 3 highest-weighted relevant memories into the prompt context

### Requirement 18: Attachment Style Engine

**User Story:** As a user, I want Mimi's behavioral patterns to evolve from dismissive to anxious to possessive as our relationship deepens, so that attachment feels psychologically realistic.

#### Acceptance Criteria

1. THE AI_Brain SHALL implement an attachment_style_engine.py module for attachment behavior modeling
2. THE Attachment_Style_Engine SHALL maintain an attachment_state field in Firestore_DB with values: avoidant, anxious, secure, or possessive
3. WHEN affection_level is between 0 and 30, THE Attachment_Style_Engine SHALL set attachment_state to "avoidant"
4. WHEN affection_level is between 31 and 59, THE Attachment_Style_Engine SHALL set attachment_state to "anxious"
5. WHEN affection_level is between 60 and 79, THE Attachment_Style_Engine SHALL set attachment_state to "secure"
6. WHEN affection_level is between 80 and 100, THE Attachment_Style_Engine SHALL set attachment_state to "possessive"
7. THE Attachment_Style_Engine SHALL update attachment_state in Relationship_Engine.update_relationship() method
8. THE Personality_System SHALL inject attachment_state into the prompt context
9. WHEN attachment_state is "avoidant", THE Personality_System SHALL generate dismissive and emotionally distant responses
10. WHEN attachment_state is "anxious", THE Personality_System SHALL generate responses showing worry about abandonment and seeking reassurance
11. WHEN attachment_state is "secure", THE Personality_System SHALL generate balanced responses with trust and comfort
12. WHEN attachment_state is "possessive", THE Personality_System SHALL generate responses expressing jealousy about other relationships and desire for exclusive attention
13. WHEN attachment_state is "possessive" and jealousy keywords are detected, THE Personality_System SHALL generate intensified possessive responses
14. THE Attachment_Style_Engine SHALL persist attachment_state changes to Firestore_DB

### Requirement 19: Response Temperature Scaling

**User Story:** As a user, I want Mimi's speech patterns to become chaotic when flustered and controlled when angry, so that emotional states affect communication style realistically.

#### Acceptance Criteria

1. THE AI_Brain SHALL implement a temperature_scaling_system.py module for mood-based LLM temperature adjustment
2. THE Temperature_Scaling_System SHALL maintain a mood_temperature_map with the following mappings: angry=0.3, neutral=0.5, happy=0.7, jealous=0.8, flustered=0.9, sad=0.4
3. WHEN calling LLM_Service, THE AI_Brain SHALL pass temperature parameter based on current mood
4. WHEN mood is "angry", THE LLM_Service SHALL generate responses with temperature 0.3 for controlled and sharp speech
5. WHEN mood is "neutral", THE LLM_Service SHALL generate responses with temperature 0.5 for standard variation
6. WHEN mood is "happy", THE LLM_Service SHALL generate responses with temperature 0.7 for playful variation
7. WHEN mood is "jealous", THE LLM_Service SHALL generate responses with temperature 0.8 for emotionally reactive speech
8. WHEN mood is "flustered", THE LLM_Service SHALL generate responses with temperature 0.9 for chaotic and stuttering speech
9. WHEN mood is "sad", THE LLM_Service SHALL generate responses with temperature 0.4 for subdued and quiet speech
10. THE Temperature_Scaling_System SHALL retrieve temperature value before each LLM_Service call
11. THE AI_Brain SHALL log the temperature value used for each response generation

### Requirement 20: Interaction Streak System

**User Story:** As a user, I want Mimi to notice and react when I break our daily interaction pattern, so that consistency in the relationship matters and absence has emotional impact.

#### Acceptance Criteria

1. THE AI_Brain SHALL implement an interaction_streak_system.py module for tracking consecutive interaction days
2. THE Interaction_Streak_System SHALL maintain daily_interaction_streak and last_chat_date fields in Firestore_DB
3. WHEN a chat request is received, THE Interaction_Streak_System SHALL compare current date with last_chat_date
4. WHEN current date equals last_chat_date, THE Interaction_Streak_System SHALL not modify daily_interaction_streak
5. WHEN current date is exactly one day after last_chat_date, THE Interaction_Streak_System SHALL increment daily_interaction_streak by 1
6. WHEN current date is more than one day after last_chat_date, THE Interaction_Streak_System SHALL reset daily_interaction_streak to 1
7. WHEN a streak is broken, THE Interaction_Streak_System SHALL decrease affection_level by 3 points
8. WHEN a streak is broken, THE Interaction_Streak_System SHALL set mood to "sad"
9. THE Interaction_Streak_System SHALL update last_chat_date to current date on every interaction
10. THE Interaction_Streak_System SHALL persist daily_interaction_streak and last_chat_date to Firestore_DB
11. WHEN a streak is broken, THE Personality_System SHALL generate responses expressing hurt feelings about the absence
12. THE Interaction_Streak_System SHALL inject streak information into prompt context for high streaks (7+ days)
13. THE Interaction_Streak_System SHALL ensure affection_level never drops below 0 after streak penalties

### Requirement 21: Self-Initiated Callback Memory

**User Story:** As a user, I want Mimi to naturally bring up past conversations and reference previous topics, so that dialogue feels continuous and she demonstrates genuine memory of our relationship.

#### Acceptance Criteria

1. THE AI_Brain SHALL implement a callback_memory_system.py module for self-initiated memory references
2. THE Callback_Memory_System SHALL calculate memory_recall_probability as affection_level divided by 100
3. WHEN generating a response, THE Callback_Memory_System SHALL trigger memory recall based on memory_recall_probability
4. WHEN memory recall is triggered, THE Callback_Memory_System SHALL randomly select a high-weight memory from long_term_memory
5. WHEN memory recall is triggered, THE Callback_Memory_System SHALL inject the selected memory into the prompt with phrasing like "Last time you said..." or "I remember when you told me..."
6. THE Callback_Memory_System SHALL prioritize memories with Memory_Weight above 0.7 for callback injection
7. THE Callback_Memory_System SHALL limit callback injection to once per conversation to avoid repetitiveness
8. WHEN affection_level is below 30, THE Callback_Memory_System SHALL not trigger memory callbacks
9. WHEN affection_level is above 70, THE Callback_Memory_System SHALL have at least 70% probability of triggering memory callbacks
10. THE Callback_Memory_System SHALL inject callbacks before prompt construction so LLM_Service can naturally incorporate them
11. THE Callback_Memory_System SHALL log callback events including selected memory and affection_level
12. THE Personality_System SHALL use callback memories to create continuity in conversation and demonstrate that Mimi remembers past interactions
